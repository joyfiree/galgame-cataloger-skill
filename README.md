# galgame-cataloger

给 galgame / 视觉小说库做 **真名考据 + 元数据补全 + 目录平铺** 的 WorkBuddy skill。

---

## 它解决什么问题

一个自己攒了几年的 galgame 库，通常长这样：

- 目录名是下载站随手起的，跟作品真名没关系（`A036@忧郁的弟弟`、`angeltear/`）
- 藏在一堆日期目录、`unknow/`、各种语义桶里
- 同一个作品有多个版本、多个副本，散落各处
- 日文原版带 DRM / 光盘校验，得靠运行补丁才启动得了
- 想入库，却不知道「这个目录到底是哪部作品」

这个 skill 要做的就是三件事：

1. **认出来**：把每个目录认成「哪一部具体作品」，附证据与置信度
2. **补全**：从 VNDB / Bangumi / DLsite 补齐厂商、标签、发售日、评分
3. **平铺**：把确认能玩的游戏提到库根，还原成一个干净的游戏库

---

## 核心设计

### 1. 本地文件优先，远端只负责「确认」

实测：一次批量考据中 9 个「不知道是什么」的游戏，**7 个从本地文件**
（`Game.ini` / `readme.txt` / `index.html` / exe 名）直接拿到确切答案，
只有 2 个需要联网，且联网主要用来交叉验证中文译名。

| 问题 | 由谁回答 |
|---|---|
| 这是什么游戏？ | **本地文件** |
| 这是不是同一个作品？ | **远端数据库**（双信号匹配） |
| 能不能平铺？ | **远端是否有对应条目** |

### 2. 原子游戏判定完全脱离远端

脚本先纯靠目录结构判断「这是不是一个能独立运行的游戏本体」，
**不看远端能不能查到**。否则会陷入循环定义（见下文问题 1）。

### 3. 平铺是一条三级漏斗

```
全部目录
   │
   ▼
L1  脚本甄别     ← 结构规律能覆盖的，约 80% 在这里解决
   ▼  漏下：UNKNOWN、语义桶目录
L2  AI 甄别      ← 判不出的逐条看实际内容，约 15%
   ▼  漏下：取哪个当本体 / 要不要展开
L3  用户甄别     ← 只剩取舍类问题，约 5%
   ▼
执行（默认 dry-run，写 manifest，可回滚）
```

**三条铁律**：逐级收窄不越级；每一级都不硬判；L2 的结论要反哺 L1。

## 遇到的问题

下面全部是实际踩过的坑，不是设想。

### 一、判定逻辑

**1. 用「远端能不能查到」判断「这是不是真游戏」——循环定义**

最早的做法是拿远端数据库当裁判：查不到就认为不是游戏。结果冤枉了一大批
Ren'Py 独走的、Unity 短作、Patreon 限定、Steam 独占作品——**远端查不到，
恰恰可能因为它不是标准 galgame，而不是因为它不是游戏。**

> 教训：原子游戏判定必须**纯结构、零联网**。先判「是不是一个能跑的游戏本体」，
> 再判「能不能和远端对上」，两件事不能混。

**2. 把「厂商确认」当作平铺依据**

厂商只回答「谁做的」，没回答「这是哪一部作品」。某厂商确认了，不代表这一部
有对应条目。

> 教训：平铺准入看的是**有没有作品级条目**，不是厂商有没有。

**3. 把旧扫描器的「语义桶」当事实**

`unknow/` 里那些桶名（`1-未解压`、`2-空壳层`、`4-破解污染`）看着像分类，
其实是**当时那个脚本为什么把它丢进来**的记录。实测 118 条：

| 桶名 | 听起来 | 实际 |
|---|---|---|
| `1-未解压/` | 都是压缩包 | 25 个里 **19 个早已解压** |
| `2-空壳层/` | 空壳、没用 | 42 个**全是「译名壳 + 内层真身」**，都可用 |
| `3-无启动程序/` | 都没 exe | 8 个里 **3 个其实有本体** |
| `4-破解污染/` | 该删的污染 | 4 个**全是能直接玩的游戏** |

> 教训：**桶名不可信，必须重新按内容判一遍。**

**4. 桶根本不是分类**

顺着上一条走到尽头：`4-破解污染/` 澄清之后，这个桶就**不该存在**了。
不是「改个名字继续挂着」，而是解散。

> 教训：**桶是临时工作台，不是永久分类。** 一个目录只要确认能玩就该平铺；
> 留在 `unknow/` 的正当理由只有一个——真的判不出来。桶清空后直接删掉。

### 二、目录识别

**5. 辅助程序被当成主程序**

`vcredist_x86.exe`（VC 运行库）被识别成游戏入口。

> 教训：辅助程序名要单独拉黑名单，且必须**锚定在 exe 上**匹配。

**6. 汉化补丁 exe 被当成本体**

`Haharanman_汉化补丁.exe` 被选为游戏主程序。

> 教训：关键词要**全文匹配**（`search` 而非 `match`）——`_汉化补丁` 在名字中间。

**7. 双扩展名漏判**

`sfa16_cn.exe.exe` 匹配不到。

> 教训：先剥一层 `.exe` 再匹配。

**8. 计数被列表覆盖，条件永真**

一处统计 SWF 命中的写法把计数变量覆盖成了列表，`1 >= 3` 恒成立，
判定逻辑静默失效。

> 教训：这种 bug 不报错、只出错结果，必须靠**自检脚本**兜住。

**9. 附属目录带数字后缀漏网**

`汉化补丁0808/` 因为带了数字后缀，没被「附属目录」规则拦住，导致一个已正确
识别的游戏**从 `game` 回归 `unknown`**。

> 教训：判据要覆盖数字后缀这类变体，改完必须跑回归。

**10. 有 `*_Data/` 就判定是游戏**

`ShutenOrder`、`2090013680` 只剩 `*_Data/` + `UnityCrashHandler64.exe`，
主程序早就没了——它们是**残骸**。

> 教训：判断 Unity 游戏必须确认**主程序 exe 在**，光有数据目录不算。

**11. 乱码目录名被当成残骸**

`偁傑儅儅傎傝偭偔/` 是 GBK 误读 Shift-JIS 的结果，里面 `amamama.exe` 运行完全正常。

> 教训：乱码是编码问题，不代表目录坏了。

**12. 「顶层全是压缩包」就判定非游戏**

一刀切误判了 18 个真游戏（白色相簿2、对魔忍、勇者大战魔物娘…）。

> 教训：先找游戏本体子目录（`find_body_subdir`），确认没有之后，再判非游戏。

### 三、认知翻转

**13. 副本误判：把唯一本体判成了冗余**

曾经认定「催眠学习 `[副本1]` 是唯一本体」，核实后发现**5 个副本全是冗余**，
白白占着约 13.0 GB。

> 教训：`[副本N]` 的判定必须看**体量/内容证据**（父层净内容 ≈ 副本体量），
> 不能靠名字猜。

**14. 破解定性完全搞反了**

最初把 `AlphaROMdiE`、`Start_Cracker`、`BepInEx` 这类文件定性为「破解污染」，
建议删除。这是**彻底错的**：

日文 galgame 原版普遍带 DRM / 光盘校验，这些文件是**免验证启动 / 正常显示**的
运行刚需。**删了游戏就跑不起来或乱码。**

> 教训：运行补丁只作**信息标注**（「自带运行补丁，勿删」），
> **绝不建议删除、绝不改变动作**。

**15. 扫描器用裸子串判「破解」**

判据是 `"cracker" in 文件名`，于是把 `Nutcrackers.mp3`（胡桃夹子 BGM）、
`ads06_cracker_pulls_01`（拉炮音效）都当成了破解工具。

> 教训：裸子串匹配必须叠加**可执行扩展名约束**，否则音效素材全中招。

### 四、远端匹配

**16. 用字符集相似度匹配**

`AngelTear` 匹配到了 `Neo Angelique`，相似度 0.95 的假阳性。

> 教训：**必须用 LCS**（最长公共子序列），字符集相似度会骗人。

**17. 看到 LCS=0 就判定不匹配**

汉字 vs 罗马字，LCS 必然为 0——跨语言场景会**全被误杀**。

> 教训：LCS 只管同语言；跨语言看 CJK 重叠。

**18. 只用目录名查远端**

可平铺率只有一半。改用**本地真名**作查询种子后，可平铺率 **+150%**。

**19. 探针不剥离括号内容**

`AngelTear[天使の涙]` 里的中文译名造成 CJK 假阳性。

> 教训：比对前先剥掉括号。

### 五、工具与操作

**20. 误删回滚凭据**

用 `ls -t | tail -n +3` 清理输出目录，把刚 `--apply` 的 `manifest_*.json`
连同 `plan.json` 一起删了——**回滚凭据没了**。

> 教训：`manifest_*` 是凭据，**只能人工确认后删**；要清就只删 `preview_*`。
> 万一手滑，可按 `_待删除/` 的实际状态反推重建，但要标 `reconstructed: true`。

**21. 子项先于父项被搬走**

平铺时父目录被掏空、游戏搬不全。

> 教训：执行器强制**按路径深度降序**执行。

**22. 两个源平铺到同名目标**

后一个直接覆盖前一个。实测 4 组重名里 **3 组其实是不同版本**，自动挑必错。

> 教训：一律不猜，全部标 `dup_dst` 跳过并成组打印，**交人工**。

**23. 往游戏目录里写元数据文件**

下轮扫描会把它们读回来当证据，形成**自我强化污染**（实测 `AngelTear`
被污染成 `Neo Angelique`）。

> 教训：元数据统一放清单文件，不往游戏目录里散落。

**24. 目录名里用 `/` 分隔信息**

Windows 立即报错 `WinError 3`，操作半途中断。

> 教训：用 `〔〕`、`（）`、` - `、`_`；**动手前先在临时目录验证一遍命名**。

**25. 新建 `_待删除/` 后被当成日期目录扫进去**

分诊计划里混进隔离区噪声行。

> 教训：统一用 `is_internal()` 判据（点开头 或 `_待删除`/`_flatten`/`_quarantine`），
> 各处**共用同一个函数**，别各写各的。

## 目录结构

```
galgame-cataloger/
├── SKILL.md                        # 完整方法论（很长，是权威文档）
├── README.md                       # 本文件
├── references/
│   ├── engines.md                  # 引擎指纹与目录结构特征
│   ├── apis.md                     # VNDB / Bangumi / DLsite API 细节
│   ├── metadataschema.md           # library.json 字段定义
│   ├── 平铺甄别模板.md              # 人工甄别报告模板
│   └── 待查清单模板.md              # D/E 级结果落地模板
└── scripts/
    ├── atomic_detect.py            # 原子游戏目录识别（六级分类，纯结构）
    ├── flatten_triage.py           # L1 平铺分诊（只读，出计划）
    ├── flatten_exec.py             # 平铺执行器（默认 dry-run，可回滚）
    ├── flatten_exec_selftest.py    # 执行器自检（合成树，不碰真实库）
    ├── channel_classify.py         # 五分类：按发行渠道决定查哪个站
    ├── scan_channels.py            # 全库渠道扫描
    ├── probe_local.py              # 抽取本地证据（编码安全）
    ├── verify_remote.py            # 远端匹配（LCS + CJK 双信号）
    └── build_manifest.py           # 并发校验，生成统一清单
```

## 快速上手

```bash
# 1. 原子目录识别（不联网，纯结构判据）
python scripts/atomic_detect.py "G:/Game" --depth 4

# 2. 抽本地证据 + 置信度分级
python scripts/probe_local.py "G:/Game/某个目录" --grade

# 3. 单个作品查远端
python scripts/verify_remote.py "作品名" --exe "game.exe" --publisher "厂商"

# 4. 批量：并发校验，生成统一清单（不往游戏目录写任何文件）
python scripts/build_manifest.py --workers 5

# 5. 平铺三级漏斗
python scripts/flatten_triage.py G:/Game --json .workbuddy/flatten/plan.json
#    → L2 对 UNKNOWN 逐条看内容，产出甄别报告
#    → L3 把取舍类问题列给用户
python scripts/flatten_exec.py .workbuddy/flatten/plan.json --only flatten
```

**所有会改文件的脚本默认 dry-run**，写 manifest，可用 `--rollback` 撤销。

## 铁律

1. **证据不足时标 `[待查]`，绝不编造。** 编造游戏名比留空更有害。
2. **绝不做「字面翻译」。** `AngelTear` 不是「天使の涙」，音译猜测不算证据。
3. **每一结论必须附证据来源。** 写清是哪个文件的哪一行 / 哪个字段。
4. **只移动/改名，不改内容。** 默认 dry-run，写 manifest，可回滚。
5. **平铺的前提是远端有对应条目。**
